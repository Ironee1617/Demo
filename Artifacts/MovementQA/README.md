# 외계인 이동과 3인칭 카메라 끊김 검증 (2026-10-18)

정속 이동인데도 최신 스냅샷을 지수 보간으로 쫓아가면서 화면 속도가 반복해서 빨라지고 느려졌다. 외계인 카메라는 보간된 기준점에서 원하는 위치를 만들고 다른 기준점에서 거리를 계산하여, 이동 중 카메라 길이도 불규칙하게 줄였다.

표시 위치를 값으로 복사한 시간별 샘플 사이에서 보간하도록 변경했다. 호스트는 시뮬레이션의 남은 틱 시간을 사용하고, 원격은 수신 상태 뒤의 표시 시간을 유지한다. 시뮬레이션·충돌·판정은 원래 호스트 상태를 사용한다. 카메라 거리 계산의 기준점을 통일하고, 실제 플레이어부터의 최종 장애물 검사는 유지했다. 로컬 입력은 매 프레임 읽고, 원격 입력·상태 전송은 타이머 잔여 시간을 보존한다.

| 일정 속도 2, 144 FPS | 수정 전 | 수정 후 |
|---|---:|---:|
| 외계인 표시 속도, 상태 30Hz | 1.4891–2.6093 | 2.0000–2.0000 |
| 외계인 카메라 속도, 상태 30Hz | 1.5802–2.5356 | 1.9999–2.0001 |
| 외계인 표시 속도, 상태 20Hz | 1.2078–2.8973 | 2.0000–2.0000 |

- 수정 전 실제 Unity 검사: 26개 실패. [원본 결과](before.txt)
- 수정 후: 외계인·위장 물고기·잠수부 × 상태 20/30Hz × 화면 60/144 FPS 통과. [결과](after.txt)
- 실제 연습 세션 60/144 FPS 검사: 속도 4.0000 전후, 표시 지연 최대 한 시뮬레이션 틱(약 33ms). 호스트의 공유 스냅샷 객체도 사용하므로 이전 좌표를 값으로 보존하는 동작을 함께 검증한다.
- 정지·경기 종료 동결·새 라운드·로비 복귀·삼킴 해제·부활을 확인했다.
- 기존 게임 규칙 검사 84개 통과. 수영 애니메이션 검사도 통과했다.

Unity 메뉴 **Aquarium → Check Movement Smoothness**, 또는 `PrototypeLab.Aquarium.Editor.AquariumMovementChecks.Run`으로 재실행한다. 20Hz 검사는 수신 주기를 재현한 표시 검사이며 실제 인터넷 왕복 지연의 측정은 아니다.

독립 복사본은 `Logs/MovementQA-20261018/Project`이며 원본과 연결된 junction/symlink 없이 파일을 복사했다. 실행 로그와 수영 검증 화면은 `Logs/MovementQA-20261018`에 남아 있다.
